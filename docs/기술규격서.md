> 퀸 주방가구 견적·원가 자동화 시스템 (Queen Kitchen OS)
> **최종 업데이트: 2026-09-10**

| 항목 | 값 |
| --- | --- |
| 버전 | 1.0.0 |
| 코드 규모 | 약 13,000줄 |
| 저장소 | Prisma + Supabase PostgreSQL (`scripts/supabase-init.sql`) |

| 프레임워크 | Express 5 + Vite 5 + React 19 |

---

## 1. 시스템 개요

상담 자료(메모·도면·사진·PDF)에서 주문 정보를 추출하고, 단가표 DB를 기준으로 결정론적으로 원가를 산출해 견적서를 발행하는 사내 자동화 시스템입니다.

```
1. 자료 입력  →  2. 규격 검수  →  3. 원가 계산  →  4. 견적서 발행
```

| 단계 | 화면 | 하는 일 |
|---|---|---|
| 1 | 자료 입력 | 도면·메모·사진 업로드, Gemini AI 정보 추출, 추출 결과 검수 |
| 2 | 규격 검수 | 고객·현장 정보 확인, 품목 확정, 단가 DB 연결, 누락 검사 |
| 3 | 원가 계산 | 품목별 산출 근거, 로스율·목표 마진율·할인·부가세 적용 |
| 4 | 견적서 발행 | 고객용 A4 미리보기, 유효기간·결제조건·특약 설정, V1/V2/V3 버전 발행 |

**AI는 입력을 돕는 수단이며, 원가 계산은 단가표 DB 기반의 결정론적 엔진(server/calculationEngine.ts)이 담당합니다.**

## 4. 데이터 계층

### 4.1 DB 스키마 (prisma/schema.prisma)

데이터베이스는 Supabase(PostgreSQL)를 사용하며, Prisma 모델(CamelCase)과 DB 테이블·컬럼(snake_case)은 `@map` 및 `@@map`으로 1:1 매핑되어 있습니다.

#### PricingItem — 단가표 (`pricing_item`)

```prisma
model PricingItem {
  id           String   @id @default(cuid())
  code         String   @unique
  category     String   // CARCASS | DOOR | COUNTERTOP | HARDWARE | APPLIANCE | LABOR | ACCESSORY
  name         String
  spec         String
  material     String
  unit         String
  costPrice    Int      @map("cost_price")    // 매입원가 (원, VAT 별도)
  sellingPrice Int      @map("selling_price") // 출고단가 (원, VAT 별도)
  supplier     String
  stockStatus  String   @default("INSTOCK") @map("stock_status")
  notes        String?
  updatedAt    DateTime @updatedAt @map("updated_at")

  @@index([category])
  @@map("pricing_item")
}
```

#### Quote — 발행된 견적서 (`quote`)

```prisma
model Quote {
  id               String   @id @default(cuid())
  quoteNumber      String   @unique @map("quote_number") // QN-20260908-001, -V2, -V3
  title            String
  status           String   @default("ISSUED")
  version          Int      @default(1)
  parentQuoteId    String?  @map("parent_quote_id")
  targetMarginRate Float    @map("target_margin_rate")

  orderEntity            Json    @map("order_entity")             // OrderEntity
  calculationResult      Json    @map("calculation_result")       // QuoteCalculationResult — 발행 시점 스냅샷
  publishMeta            Json?   @map("publish_meta")             // QuotePublishMeta
  appliedPricingSnapshot Json?   @map("applied_pricing_snapshot") // PricingItem[] (호환용)
  companyInfo            Json    @map("company_info")             // { name, representative, bizNumber, address, phone, email }
  notes                  String?

  draftId   String?  @map("draft_id")
  draft     Draft?   @relation(fields: [draftId], references: [id], onDelete: SetNull)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@index([status, createdAt])
  @@map("quote")
}
```

#### Draft — 견적 초안 (`draft`)

```prisma
model Draft {
  id       String @id @default(cuid())
  status   String @default("ACTIVE") // ACTIVE | PUBLISHED | ARCHIVED
  revision Int    @default(1)        // 낙관적 잠금 카운터
  payload  Json                      // DraftPayload — 현재 상태만 (이력은 아래 테이블로)

  // 목록 조회를 payload 파싱 없이 처리하기 위한 비정규화 컬럼
  customerName       String  @default("") @map("customer_name")
  projectName        String  @default("") @map("project_name")
  step               Int     @default(1)
  totalAmount        Int?    @map("total_amount")

  pricingFingerprint String? @map("pricing_fingerprint")
  lastEditorId       String? @map("last_editor_id")
  publishedQuoteIds  Json    @default("[]") @map("published_quote_ids")

  revisions QuoteDraftRevision[]
  quotes    Quote[]
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@index([status, updatedAt])
  @@map("draft")
}
```

#### QuoteDraftRevision — 초안 변경 이력 (`quote_draft_revision`)

```prisma
model QuoteDraftRevision {
  id       Int      @id @default(autoincrement())
  draftId  String   @map("draft_id")
  draft    Draft    @relation(fields: [draftId], references: [id], onDelete: Cascade)
  revision Int
  label    String   // 자동 저장 | 수동 임시 저장 | 단계 이동 | rev.N 상태로 복구
  payload  Json     // DraftPayload (appliedPricingSnapshot 제외 — 용량 절감)
  savedAt  DateTime @default(now()) @map("saved_at")

  @@unique([draftId, revision])
  @@index([draftId, savedAt])
  @@map("quote_draft_revision")
}
```

### 4.1.5 실제 Supabase DDL (scripts/supabase-init.sql)

Supabase 대시보드 **SQL Editor**에서 실행할 수 있는 PostgreSQL DDL입니다. 모든 테이블명과 컬럼명은 snake_case 네이밍 규칙을 준수합니다.

```sql
-- 1. pricing_item 테이블
CREATE TABLE IF NOT EXISTS "pricing_item" (
    "id"           TEXT             NOT NULL,
    "code"         TEXT             NOT NULL,
    "category"     TEXT             NOT NULL,
    "name"         TEXT             NOT NULL,
    "spec"         TEXT             NOT NULL,
    "material"     TEXT             NOT NULL,
    "unit"         TEXT             NOT NULL,
    "cost_price"   INTEGER          NOT NULL,
    "selling_price" INTEGER         NOT NULL,
    "supplier"     TEXT             NOT NULL,
    "stock_status" TEXT             NOT NULL DEFAULT 'INSTOCK',
    "notes"        TEXT,
    "updated_at"   TIMESTAMPTZ      NOT NULL DEFAULT now(),
    CONSTRAINT "pricing_item_pkey" PRIMARY KEY ("id")
);

-- 2. draft 테이블 (quote보다 먼저 생성 — FK 참조 대상)
CREATE TABLE IF NOT EXISTS "draft" (
    "id"                  TEXT        NOT NULL,
    "status"              TEXT        NOT NULL DEFAULT 'ACTIVE',
    "revision"            INTEGER     NOT NULL DEFAULT 1,
    "payload"             JSONB       NOT NULL,
    "customer_name"       TEXT        NOT NULL DEFAULT '',
    "project_name"        TEXT        NOT NULL DEFAULT '',
    "step"                INTEGER     NOT NULL DEFAULT 1,
    "total_amount"        INTEGER,
    "pricing_fingerprint" TEXT,
    "last_editor_id"      TEXT,
    "published_quote_ids" JSONB       NOT NULL DEFAULT '[]'::jsonb,
    "created_at"          TIMESTAMPTZ NOT NULL DEFAULT now(),
    "updated_at"          TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT "draft_pkey" PRIMARY KEY ("id")
);

-- 3. quote 테이블
CREATE TABLE IF NOT EXISTS "quote" (
    "id"                       TEXT             NOT NULL,
    "quote_number"             TEXT             NOT NULL,
    "title"                    TEXT             NOT NULL,
    "status"                   TEXT             NOT NULL DEFAULT 'ISSUED',
    "version"                  INTEGER          NOT NULL DEFAULT 1,
    "parent_quote_id"          TEXT,
    "target_margin_rate"       DOUBLE PRECISION NOT NULL,
    "order_entity"             JSONB            NOT NULL,
    "calculation_result"       JSONB            NOT NULL,
    "publish_meta"             JSONB,
    "applied_pricing_snapshot" JSONB,
    "company_info"             JSONB            NOT NULL,
    "notes"                    TEXT,
    "draft_id"                 TEXT,
    "created_at"               TIMESTAMPTZ      NOT NULL DEFAULT now(),
    "updated_at"               TIMESTAMPTZ      NOT NULL DEFAULT now(),
    CONSTRAINT "quote_pkey"          PRIMARY KEY ("id"),
    CONSTRAINT "quote_draft_id_fkey" FOREIGN KEY ("draft_id")
        REFERENCES "draft" ("id") ON DELETE SET NULL ON UPDATE CASCADE
);

-- 4. quote_draft_revision 테이블
CREATE TABLE IF NOT EXISTS "quote_draft_revision" (
    "id"       SERIAL      NOT NULL,
    "draft_id" TEXT        NOT NULL,
    "revision" INTEGER     NOT NULL,
    "label"    TEXT        NOT NULL,
    "payload"  JSONB       NOT NULL,
    "saved_at" TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT "quote_draft_revision_pkey"          PRIMARY KEY ("id"),
    CONSTRAINT "quote_draft_revision_draft_id_fkey" FOREIGN KEY ("draft_id")
        REFERENCES "draft" ("id") ON DELETE CASCADE ON UPDATE CASCADE
);

-- 5. 인덱스
CREATE UNIQUE INDEX IF NOT EXISTS "pricing_item_code_key"
    ON "pricing_item"("code");
CREATE INDEX        IF NOT EXISTS "pricing_item_category_idx"
    ON "pricing_item"("category");
CREATE UNIQUE INDEX IF NOT EXISTS "quote_quote_number_key"
    ON "quote"("quote_number");
CREATE INDEX        IF NOT EXISTS "quote_status_created_at_idx"
    ON "quote"("status", "created_at");
CREATE INDEX        IF NOT EXISTS "draft_status_updated_at_idx"
    ON "draft"("status", "updated_at");
CREATE INDEX        IF NOT EXISTS "quote_draft_revision_draft_id_saved_at_idx"
    ON "quote_draft_revision"("draft_id", "saved_at");
CREATE UNIQUE INDEX IF NOT EXISTS "quote_draft_revision_draft_id_revision_key"
    ON "quote_draft_revision"("draft_id", "revision");
```

> **참고**: Supabase 환경에서는 PostgreSQL의 `JSONB` 타입과 `TIMESTAMPTZ`를 사용하며, 테이블과 컬럼 모두 snake_case 네이밍으로 정의되어 있어 Supabase 대시보드 Table Editor 및 SQL 쿼리와 완벽히 호환됩니다.

### 4.2 저장 정책


| 항목 | 정책 |
|---|---|
| 자동 저장 주기 | 입력 멈춤 후 1.5초 / 최대 15초 간격 |
| 저장 방식 | `QuoteDraftRevision` 행 insert — 파일 전체 재작성 없음 |
| 이력 보관 수 | 초안당 최근 **20개** (`MAX_DRAFT_HISTORY`) |
| ACTIVE → ARCHIVED | 30일간 수정 없으면 자동 전환 (`ARCHIVE_AFTER_DAYS = 30`) |
| ARCHIVED → 삭제 | 보관 전환 후 90일 추가 경과 시 영구 삭제 (`PURGE_AFTER_DAYS = 90`) |
| 예외: 발행 이력 있는 초안 | 삭제하지 않음 (이력 가치 보존) |
| appliedPricingSnapshot | 초안 revision에는 저장하지 않음. 발행된 견적서(`Quote`)에만 스냅샷 보관 |
| 단가 지문 | SHA-1 해시 16자. 계산 결과 갱신 시 함께 갱신. 단가 변경 안내에 사용 |
| 보관·폐기 실행 시점 | 서버 기동 시 1회 (`runDraftRetention()`) |

### 4.3 낙관적 잠금 (동시 편집 충돌 방지)

`Draft.revision` 정수를 카운터로 사용합니다.

1. 클라이언트가 초안을 열 때 `revision` 값을 기억합니다.
2. 저장 요청 시 기억한 `revision`을 함께 전송합니다.
3. 서버에서 DB의 `revision`과 비교합니다.
   - 일치 → 저장 성공, `revision += 1`
   - 불일치 → **409 Conflict** 응답 + 서버 최신본 반환
4. 클라이언트는 충돌 시 `최신본 불러오기 / 이 창 내용으로 덮어쓰기`를 선택합니다.

### 4.4 저장소 전환 이력

| 전환 전 | 전환 후 | 시점 |
|---|---|---|
| `data/db.json` (파일 전체 동기 재작성) | `data/queen-os.db` (Prisma + SQLite) | 2026-09-10 (Phase 1) |
| `data/queen-os.db` (로컬 SQLite 파일) | **Supabase PostgreSQL (`pricing_item` 등 snake_case)** | 2026-09-10 (Phase 2 완료) |
| 자동 저장 1회당 1.1 MB 이상 쓰기 | 자동 저장 1회당 row 1개 insert (~0.02 MB) | — |
| 마이그레이션 수동 처리 | Supabase SQL Editor (`supabase-init.sql`) + Prisma | — |

레거시 JSON에서의 이관은 `npm run db:migrate-legacy-json` 1회 실행으로 처리되었으며, Supabase 초기화는 `scripts/supabase-init.sql`을 통해 완료되었습니다.

## 5. API 명세

모든 성공 응답: `{ success: true, data: ... }`  
모든 실패 응답: `{ success: false, error: "..." }`

### 5.1 단가표 (`/api/pricing`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/pricing` | 단가 목록 (쿼리: `search`, `category`) |
| GET | `/api/pricing/fingerprint` | 단가표 지문 조회 |
| GET | `/api/pricing/:id` | 단가 단건 조회 |
| POST | `/api/pricing` | 단가 등록 |
| PUT | `/api/pricing/:id` | 단가 수정 |
| DELETE | `/api/pricing/:id` | 단가 삭제 |
| POST | `/api/pricing/bulk` | 일괄 upsert (`code` 또는 `name` 기준) |
| POST | `/api/pricing/reset-seed` | 기본 카탈로그로 초기화 |

> `/api/pricing/fingerprint`는 `/api/pricing/:id` 보다 먼저 선언되어야 `:id`로 잡히지 않습니다.

검색(`search`)은 `name`, `code`, `material`, `spec`, `supplier` 5개 컬럼에 SQLite LIKE 부분일치를 적용합니다.

### 5.2 AI 파싱 (`/api/gemini`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/gemini/parse-doc` | 문서(PDF·이미지·텍스트) → 단가 품목 추출 |
| POST | `/api/gemini/parse-order` | 메모·이미지 → `OrderEntity` 추출 |

- `GEMINI_API_KEY` 미설정 시 휴리스틱 파서로 자동 폴백합니다.
- multipart/form-data(`file`/`image` 필드) 또는 JSON(`base64File`+`mimeType`) 모두 지원합니다.
- 최대 파일 크기: 25 MB.

### 5.3 원가 계산 (`/api/quote`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/quote/calculate` | `OrderEntity` → `QuoteCalculationResult` 반환 |

계산은 단가표 DB 조회 후 결정론적으로 수행합니다. 외부 상태나 난수가 없습니다.

### 5.4 견적서 (`/api/quotes`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/quotes` | 견적서 목록 (쿼리: `status`, `search`) |
| GET | `/api/quotes/:id` | 견적서 단건 (id 또는 quoteNumber로 조회) |
| POST | `/api/quotes` | 견적서 발행 (동시에 초안을 PUBLISHED로 전환) |
| PUT | `/api/quotes/:id` | 견적서 메타 수정 (상태·메모·발행 정보) |
| DELETE | `/api/quotes/:id` | 견적서 삭제 |

발행 번호 형식: `QN-YYYYMMDD-NNN` (당일 발행 순번, 3자리 패딩).  
재발행 시 새 문서 생성 + `parentQuoteId`로 최초 버전 연결.

> 검색 시 `orderEntity`는 JSON 컬럼이라 SQLite LIKE가 불가합니다.  
> `quoteNumber`·`title`은 DB, 고객명·주소·연락처는 애플리케이션 레벨에서 2중 필터링합니다.

### 5.5 견적 초안 (`/api/drafts`)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/drafts` | 초안 생성 |

### 7.4 도어 면적 산출식

```
도어면적(m²) = 하부장(m) × 0.72
             + 상부장(m) × 0.68
             + 아일랜드(m) × 0.72 × 1.5
             + 키큰장폭(m) × 2.1          (있을 때)
             + 냉장고장폭(m) × 0.5        (있을 때)
```

### 7.5 단가 조회 우선순위 (`lookupItem`)

1. 품목코드(`code`) 정확 일치
2. 품목명(`name`) 부분 일치 (대소문자 무시)
3. 카테고리 내 첫 번째 품목 (폴백)
4. 모두 실패 → 임시 기본 단가 생성 + `ValidationItem(WARNING)` 추가

### 7.6 집계 및 최종 금액

| 항목 | 산식 |
|---|---|
| 총 제조원가 | 모든 품목 `costTotal` 합산 |
| 총 공급가액 | 모든 품목 `sellingTotal` 합산 |
| 총 마진액 | 공급가액 - 제조원가 |
| 평균 마진율 | 마진액 / 공급가액 × 100 (소수점 1자리) |
| 부가세 | 공급가액 × 10% (원 미만 반올림) |
| **최종 견적 총액** | **공급가액 + 부가세** |

## 12. 향후 개선 계획

현재 코드베이스에서 완료된 항목(Prisma/Supabase PostgreSQL, Zod, 낙관적 잠금, snake_case DDL 등)을 제외한 잔여 개선 사항입니다.

### 12.1 착수 조건부 항목

| 항목 | 착수 신호 | 상태 |
|---|---|---|
| **SQLite → PostgreSQL (Supabase)** | 원격 배포 및 확장성 확보 | **✅ 2026-09-10 완료 (`supabase-init.sql`)** |
| **인증 도입** (Auth.js 또는 Lucia) | 2명 이상이 서로 다른 PC에서 동시에 사용 시작 시 | 대기 |
| **원격 배포** (Fly.io / Railway / Vercel) | 현장에서 휴대폰으로 견적 확인이 필요할 때 | 대기 |
| **Next.js 전환** | 외부 고객이 견적서 링크를 직접 열람하는 기능이 필요할 때 | 보류 |

### 12.2 코드 품질 개선 (독립적으로 착수 가능)

| 항목 | 효과 |
|---|---|
| **TanStack Query** | 캐시·재검증·낙관적 업데이트, 자동 저장 코드 단순화 |
| **React Router / TanStack Router** | 새로고침 시 탭 유지, 특정 견적서 링크 공유, 뒤로가기 동작 |

| **Vitest 도입** | `calculationEngine.ts` 단위 테스트 (순수 함수, 비용 낮음, 돈이 걸린 코드) |
