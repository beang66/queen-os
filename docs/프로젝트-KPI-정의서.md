# Queen-OS 프로젝트 KPI (핵심 성과 지표) 정의서

> **퀸 주방가구 견적·원가 자동화 시스템 (Queen Kitchen OS)**  
> **문서 버전:** 1.0.0  
> **작성일자:** 2026-09-10  
> **대상 시스템:** Queen-OS (견적/원가 계산 엔진, AI 파서, 초안/이력 관리, 단가표 DB)

---

## 1. 개요 및 배경

### 1.1 수립 목적
Queen-OS는 주방가구 맞춤 견적 업무의 복잡성(다양한 규격, 자재, 하드웨어, 옵션 계산)과 수기 계산에 따른 인적 오류, 리드타임 지연 문제를 해결하기 위해 구축된 내부 업무 자동화 솔루션입니다.
본 문서는 Queen-OS의 도입 및 운영 효과를 정량적·정성적으로 측정하고, 지속적인 시스템 개선과 비즈니스 가치 창출을 견인하기 위한 **핵심 성과 지표(Key Performance Indicators, KPI)**를 정의합니다.

### 1.2 지표 프레임워크 체계
지표는 상호 유기적으로 연결된 4대 핵심 영역으로 분류하여 관리합니다.

```

└──────────────────────────────┬──────────────────────────────┘
                               │

 1. 비즈니스 성과        2. 업무 운영 효율성      3. 시스템/기술 품질

  - 견적 리드타임 단축    - 작성 소요 시간 단축   - 계산 엔진 응답 속도
```

## 3. 영역별 상세 KPI 정의

### 3.1 비즈니스 성과 지표 (Business Value KPIs)

#### KPI B-1: 견적 발행 리드타임 단축률 (Quote Lead Time)
- **정의**: 고객의 상담 자료(도면, 메모 등) 접수 시점부터 최종 고객용 견적서(A4 PDF/발행본) 출력 완료 시점까지 소요되는 총 시간.
- **측정 공식**:
  $$\text{리드타임 단축률(\%)} = \frac{\text{기존 평균 소요시간 (120분)} - \text{시스템 사용 소요시간}}{\text{기존 평균 소요시간 (120분)}} \times 100$$
- **목표치**:
  - 기존: 120분/건
  - 1단계(안정화): 15분 이내 (87.5% 단축)
  - 2단계(고도화): 5분 이내 (95.8% 단축)
- **비즈니스 효과**: 고객 문의 당일 즉시 견적 전달이 가능해져 상담 이탈률 최소화 및 고객 신뢰도 극대화.

#### KPI B-2: 목표 마진율 준수율 및 계산 오차 방어 (Margin Protection)
- **정의**: 견적 작성 시 지정한 목표 마진율(`quote.target_margin_rate`)과 실제 출고/시공 정산 시 실현된 마진율 간의 괴리율.
- **측정 공식**:
  $$\text{마진 괴리율(\%)} = |\text{견적 목표 마진율(\%)} - \text{실제 정산 마진율(\%)}|$$
- **목표치**:
  - 과거: 자재 할증 누락, 시공 부자재 누락 등으로 인한 마진 침식(평균 3~5%p 오차 발생)
  - 시스템 목표: **괴리율 0.5%p 미만** (단가표 기반 결정론적 로스율 및 매입단가 자동 적용)
- **비즈니스 효과**: 견적 단계의 계산 착오로 인한 기업 손실을 원천 차단하여 수익성 보장.

#### KPI B-3: 견적 수주 전환율 (Quote-to-Order Conversion Rate)
- **정의**: 시스템에서 발행된 전체 견적 건수 중 실제 발주/계약(`CONFIRMED` / `IN_PRODUCTION`)으로 이어진 비율.
- **측정 공식**:
  $$\text{수주 전환율(\%)} = \frac{\text{계약 확정 견적 수 (`quote.status = 'CONFIRMED'`) } } {\text{총 발행 견적 수 (`quote.status = 'ISSUED'`) } } \times 100$$
- **목표치**: 기존 22% → 1차 목표 35% → 2차 목표 45%
- **관리 방안**: 신속한 재견적(V1 → V2 → V3 발행 기능, `parent_quote_id` 체인) 대응 시간을 10분 이내로 줄여 고객과의 협상 테이블 주도권 확보.

### 3.2 업무 및 운영 프로세스 효율성 지표 (Operations KPIs)

#### KPI O-1: 4단계 견적 마법사 단계별 완결율 (Funnel Conversion)
- **정의**: Step 1(자료 입력)에서 시작하여 Step 4(견적서 발행)까지 이탈 없이 도달하는 비율.
  ```
  Step 1 (자료 입력) ───[100%]───►
  Step 2 (규격 검수) ───[ 95%]───►
  Step 3 (원가 계산) ───[ 92%]───►
  Step 4 (견적서 발행) ──[ 88%]
  ```
- **모니터링 항목**:
  - Step 1 → Step 2 전환율: AI 파싱 후 검수 착수 비율
  - Step 2 → Step 3 전환율: 품목 매핑 및 치수 입력 완료율
  - Step 3 → Step 4 전환율: 마진율/할인율 확정 및 발행 완료율
- **목표치**: 전체 퍼널 최종 완료율 **85% 이상** 달성.

#### KPI O-2: AI 문서/자연어 파싱 정확도 및 수정률 (AI Parsing Accuracy)
- **정의**: 업로드된 도면·메모·치수 텍스트에서 Gemini AI가 추출한 필드(고객명, 주소, 레이아웃, 장별 치수, 도어/상판 재질, 기기) 중 검수자가 수정 없이 그대로 승인한 비율.
- **측정 공식**:
  $$\text{AI 자동 채택률(\%)} = \frac{\text{수정되지 않은 추출 필드 수}}{\text{전체 추출 필드 수}} \times 100$$
- **목표치**:
  - 치수/레이아웃: 90% 이상
  - 품목/자재 코드 매핑: 80% 이상
  - 종합 자동 채택률: 85% 이상 유지

#### KPI O-3: 견적 누락 방지 적중률 (Pre-flight Validation Zero-Miss)
- **정의**: 필수 부속(손잡이, 걸레받이, 마감재, 시공비, 운반비)이나 규격 이상(높이/깊이 불일치)을 시스템이 사전에 경고(`ValidationItem`)하여 누락 발주를 방지한 비율.
- **목표치**: **현장 시공 중 미발주/누락 발생률 0건 (100% 차단)**
- **측정 기준**:
  - Step 2/Step 3에서 발행된 `WARNING` 및 `BLOCKING` 유효 경고 건수 트래킹.

#### KPI O-4: 초안 저장 및 작업 복구 성공률 (Draft Continuity)
- **정의**: 예기치 못한 브라우저 종료, 네트워크 단절, 이동 중 작업 중단 시 기존 작업 상태가 손실 없이 복원된 비율.
- **목표치**: **작업 손실률 0% (복구 성공률 99.9%)**
- **기술적 보장**:
  - 디바운스 1.5초 / 최대 15초 주기 자동 저장
  - 클라이언트 `localStorage` 백업 연동
  - Revision 이력 20개 저장 및 롤백 기능 제공

### 3.3 시스템 및 엔지니어링 품질 지표 (Engineering KPIs)

#### KPI E-1: 원가 계산 엔진 응답 속도 (Calculation Latency)
- **정의**: `calculationEngine.ts`가 호출되어 하부장, 상부장, 아일랜드, 키큰장, 도어, 상판, 하드웨어, 시공비 등 7개 카테고리 품목의 원가/공급가/마진을 결정론적으로 산출하고 결과를 반환하는 시간.
- **목표치**:
  - **P95: 50ms 미만**
  - **P99: 100ms 미만**
- **품질 기준**: 엑셀 매크로 대비 100배 이상의 연산 반응성을 유지하여 실시간 마진율/할인율 슬라이더 조작 시 버벅임 없는 UI 경험 제공.

#### KPI E-2: API 응답 성능 및 가용성 (Availability & Latency)
- **정의**: 주요 API 엔드포인트의 처리 속도 및 서버 가동률.
- **세부 목표**:
  | 엔드포인트 | 역할 | 목표 응답 속도 (P95) | 목표 가용성 |
  |---|---|---|---|
  | `POST /api/quotes/calculate` | 원가 계산 API | **< 80ms** | 99.9% |
  | `POST /api/drafts` | 초안 자동저장 API | **< 100ms** | 99.9% |
  | `GET /api/pricing` | 단가표 전건 조회 | **< 50ms** | 99.9% |
  | `POST /api/ai/parse` | Gemini 파싱 | **< 3,500ms** (AI 연동) | 98.0% (휴리스틱 폴백 100%) |

#### KPI E-3: 데이터 타입 및 스키마 무결성 (Schema Drift Zero)
- **정의**: 프론트엔드-백엔드 간 데이터 교환 시 발생할 수 있는 스키마 불일치(Drift) 방지 지표.
- **측정 기준**:
  - `src/schemas.ts` Zod 스키마와 `src/types.ts` 간 타입 호환성 테스트 100% 통과
  - TypeScript `strictNullChecks: true` 컴파일 에러: **0건 유지**
  - 클라이언트 `fetchValidated` 런타임 스키마 불일치 에러: **0건 유지**

#### KPI E-4: 동시성 충돌 감지 및 방어율 (Concurrency Safety)
- **정의**: 동일 초안을 복수의 세션 또는 탭에서 수정할 때 발생하는 덮어쓰기 유실 방지율.
- **지표**:
  - 낙관적 잠금(Revision 번호 대조)을 통한 충돌 감지율: **100%**
  - 409 Conflict 발생 시 사용자 선택 UI(`최신본 불러오기 / 덮어쓰기`) 표출 성공률: **100%**

### 3.4 데이터 거버넌스 및 신뢰성 지표 (Data Governance KPIs)

#### KPI D-1: 단가표 정합성 및 변경 추적율 (Pricing Freshness)

## 4. KPI 측정 주기 및 관리 프로세스

### 4.1 측정 및 보고 주기

```
┌─────────────────────────────────────────────────────────────┐
│                    KPI 모니터링 주기 체계                   │
├───────────────┬───────────────────────────────┬─────────────┤
│ 주기          │ 대상 지표                     │ 담당자      │
├───────────────┼───────────────────────────────┼─────────────┤
│ 실시간 (상시) │ 시스템 가동률, 계산 엔진 레이턴시, 스키마 에러│ 개발팀      │
│ 주간 (Weekly) │ 견적 리드타임, 작성 소요시간, AI 채택률       │ 운영/개발팀 │
│ 월간 (Monthly)│ 견적 수주율, 마진 방어율, 초안 완료율        │ 경영/영업팀 │
│ 분기 (Quarter)│ 누적 단가표 갱신 주기, 시스템 ROI 정산       │ 전사        │
└───────────────┴───────────────────────────────┴─────────────┘
```

### 4.2 데이터 수집 및 집계 방법
1. **견적 및 초안 로그 분석 (Supabase PostgreSQL DB 기반)**:
   - `quote` 테이블 (`prisma.quote`): 발행 일시(`created_at`), 수주 상태(`status`), 버전(`version`), 목표 마진율(`target_margin_rate`), 주문 엔티티(`order_entity`), 계산 결과(`calculation_result`).
   - `draft` 테이블 (`prisma.draft`): 초안 작성 시작(`created_at`), 최종 갱신(`updated_at`), 진행 단계(`step`), 현재 리비전(`revision`), 최종 견적 캐시(`total_amount`).
   - `quote_draft_revision` 테이블 (`prisma.quoteDraftRevision`): 저장 시점(`saved_at`), 레이블(`label`), 초안 외래키(`draft_id`).
2. **원가 산출 검증 로그**:
   - `quote.applied_pricing_snapshot` 및 `pricing_item` 최신 단가표를 활용하여 계산 당시 단가와 공급 계약 단가 비교.
3. **클라이언트 성능 지표**:
   - `window.performance` API를 활용한 Step 전환 시간 및 API 호출 Latency 모니터링.

## 5. 지표 개선을 위한 단계별 액션 플랜

### Phase 1: 기반 안정화 및 지표 모니터링 체계 가동 (현재 ~ 1개월)
- **주요 목표**: 견적 시간 15분 달성, 스키마 드리프트 0건 유지.
- **핵심 과제**:
  - Supabase PostgreSQL(`quote`, `draft`, `quote_draft_revision`) 메타데이터 기반 리드타임 통계 쿼리 구축.
  - Zod 검증 실패 및 409 충돌 이벤트 로깅 세분화.
  - 기본 단가표(`pricing_item`)의 최신 시장가 동기화 (`scripts/supabase-init.sql` 기준).

### Phase 2: 운영 효율화 및 품질 고도화 (1개월 ~ 3개월)
- **주요 목표**: AI 파싱 자동 채택률 85% 이상, Vitest 도입을 통한 계산 엔진 테스트 커버리지 90% 이상 확보.
- **핵심 과제**:
  - `calculationEngine.ts` 대상 단위 테스트 스위트 구축 (엣지 케이스 100% 검증).
  - 프론트엔드 TanStack Query 도입으로 네트워크 캐싱 및 초안 저장 대기 시간 최소화.
  - 자주 사용하는 주방 레이아웃(ㄱ자, ㄷ자, 대면형 아일랜드) 템플릿 프리셋 제공.

### Phase 3: 비즈니스 가치 확장 (3개월 이후)
- **주요 목표**: 견적 수주 전환율 45% 달성, 모바일/현장 지원.
- **핵심 과제**:
  - 고객용 웹 견적서 링크 공유 기능 (모바일 반응형 뷰어).
  - 견적 조건별(자재 옵션 V1/V2/V3) 비교 견적서 원클릭 생성 기능.
  - 공급업체 단가 변동 시 기존 미체결 견적에 미치는 영향도 자동 분석 리포트.

## 6. 결론 및 기대 효과 (ROI)

Queen-OS의 KPI 체계 도입을 통해 다음과 같은 정량적 비즈니스 가치 창출이 기대됩니다.

1. **인건비 및 시간 절감**:
   - 건당 견적 소요 시간 120분 → 15분 (약 **87%의 업무 공수 절감**)
   - 월 100건 견적 기준: 월 **175시간의 업무 시간 절약** (전문 설계 인력의 핵심 상담 집중 가능)
2. **수익성 보호 (마진 침식 방지)**:
   - 복잡한 자재(엔지니어드스톤, 도장 도어, 특수 하드웨어) 및 시공비 누락 0건화.
   - 연간 견적 총액 기준 약 **2~3%의 원가 누수 방지 효과**.
3. **고객 만족도 및 수주 경쟁력 강화**:
   - 상담 현장 또는 당일 즉시 정확한 세부 견적서 제공으로 수주율 13%p 이상 향상.
