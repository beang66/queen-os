## 판정

**지금 시스템의 한계는 프론트엔드 프레임워크가 아니라 JSON 파일 저장소에서 옵니다.**

`server/db.ts`의 `save()`는 파일 전체를 `fs.writeFileSync`로 동기 재작성합니다. 견적 초안 자동 저장이 1.5초마다 이 함수를 호출합니다. 저장할 내용이 한 글자든 파일 전체가 다시 쓰입니다. Next.js로 옮기든 NestJS를 얹든 이 동작은 그대로 남습니다.

반대로 React 19 + Vite + TypeScript + Tailwind 조합에는 문제가 없습니다. 컴포넌트 경계도 깨끗합니다. 여기를 갈아엎는 것은 비용만 크고 얻는 것이 없습니다.

## 측정 근거

견적서 3건, 초안 4건, 단가 품목 28건밖에 없는 상태에서 측정한 값입니다.

| 지표 | 값 | 비고 |
| --- | --- | --- |
| db.json 파일 크기 | **1.1 MB** | 자동 저장 1회마다 이 전체가 다시 쓰임 |
| 초안이 차지하는 비중 | **89%** | 482 KB / 540 KB (직렬화 기준) |
| revision 1개 크기 | **15.5 KB** | 초안당 최대 20개 보관 |
| 12개월 후 추정 | **145 MB** | 월 20건 · 초안당 revision 20 기준 |

### 구성 요소별 비중

| 구성 요소 | 크기 | 설명 |
| --- | --- | --- |
| `drafts` (4건) | 482.0 KB | revision 이력이 payload 전체를 통째로 복제 |
| `quotes` (3건) | 48.9 KB | 발행된 견적서 — 스냅샷 보관이 정당함 |
| `pricingItems` (28건) | 9.6 KB | 단가표 원본 |

### 초안 1건을 열어보면

| 계층 | 크기 | 문제 |
| --- | --- | --- |
| `history` (7 revision) | 49.0 KB | 저장 1회마다 payload 전체가 새 항목으로 추가됨 |
| └ `payload` 1개 | 15.5 KB | — |
| 　└ `calculationResult` | 12.3 KB | payload의 79% |
| 　　└ `appliedPricingSnapshot` | 6.1 KB | **단가표 전체 복사본이 revision마다 중복 저장** |

### 자동 저장 1회당 쓰기 용량

| 시점 | 현재 구조 | 전환 후 |
| --- | --- | --- |
| 지금 | 1.1 MB | 0.02 MB |
| 6개월 | 73 MB | 0.02 MB |
| 12개월 | **145 MB** | 0.02 MB |

현재 구조에서는 데이터가 쌓일수록 저장 비용이 함께 커집니다. 12개월 시점에는 1.5초 간격의 자동 저장이 145 MB 동기 쓰기를 일으켜 이벤트 루프가 멈춥니다. 전환 후에는 row 1개 insert이므로 데이터량과 무관하게 일정합니다.

### 작업

- [x] Prisma 스키마 작성 — `PricingItem` / `Quote` / `Draft` / `QuoteDraftRevision`
- [x] `QuoteDraftRevision`을 별도 테이블로 분리 (지금은 `history[]` 배열로 payload 전체를 복제)

- Prisma Studio — 담당자가 데이터를 GUI로 직접 확인 가능
- PostgreSQL 전환은 `provider` 한 줄 + 연결 문자열

## Phase 3 — Next.js 검토

**시점: 조건부 · 지금은 아님**

> **착수 신호** — 외부 고객이 견적서 링크를 직접 열어보는 기능이 필요해질 때. 그때 SSR·메타태그·이미지 최적화가 값을 합니다.

그 전까지는 전환 이득이 없습니다. 이 앱의 핵심은 4단계 마법사, 즉 무거운 클라이언트 상태이고 React Server Components가 도와줄 수 있는 영역이 아닙니다. 마법사 상태는 어차피 클라이언트에 남고 빌드 복잡도만 늘어납니다.

## Prisma 스키마 (Supabase PostgreSQL 매핑)

`scripts/supabase-init.sql`과 1:1 대응되도록 테이블명과 컬럼명이 snake_case로 매핑되어 있습니다.

```prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

model PricingItem {
  id           String   @id @default(cuid())
  code         String   @unique
  category     String   // CARCASS | DOOR | COUNTERTOP | HARDWARE | APPLIANCE | LABOR | ACCESSORY
  name         String
  spec         String
  material     String
  unit         String
  costPrice    Int      @map("cost_price")
  sellingPrice Int      @map("selling_price")
  supplier     String
  stockStatus  String   @default("INSTOCK") @map("stock_status")
  notes        String?
  updatedAt    DateTime @updatedAt @map("updated_at")

  @@index([category])
  @@map("pricing_item")
}

model Quote {
  id               String   @id @default(cuid())
  quoteNumber      String   @unique @map("quote_number")
  title            String
  status           String   @default("ISSUED")
  version          Int      @default(1)
  parentQuoteId    String?  @map("parent_quote_id")
  targetMarginRate Float    @map("target_margin_rate")

  orderEntity            Json    @map("order_entity")
  calculationResult      Json    @map("calculation_result")
  publishMeta            Json?   @map("publish_meta")
  appliedPricingSnapshot Json?   @map("applied_pricing_snapshot")
  companyInfo            Json    @map("company_info")
  notes                  String?

  draftId   String?  @map("draft_id")
  draft     Draft?   @relation(fields: [draftId], references: [id], onDelete: SetNull)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@index([status, createdAt])
  @@map("quote")
}

model Draft {
  id       String @id @default(cuid())
  status   String @default("ACTIVE")
  revision Int    @default(1)
  payload  Json

  customerName       String  @default("") @map("customer_name")
  projectName        String  @default("") @map("project_name")
  step               Int     @default(1)
  totalAmount        Int?    @map("total_amount")

  pricingFingerprint String? @map("pricing_fingerprint")
  lastEditorId       String? @map("last_editor_id")
  publishedQuoteIds  Json    @default("[]") @map("published_quote_ids")

  revisions QuoteDraftRevision[]
  quotes    Quote[]
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@index([status, updatedAt])
  @@map("draft")
}

model QuoteDraftRevision {
  id       Int      @id @default(autoincrement())
  draftId  String   @map("draft_id")
  draft    Draft    @relation(fields: [draftId], references: [id], onDelete: Cascade)
  revision Int
  label    String
  payload  Json
  savedAt  DateTime @default(now()) @map("saved_at")

  @@unique([draftId, revision])
  @@index([draftId, savedAt])
  @@map("quote_draft_revision")
}
```

## 이관 스크립트 개요

```ts
// scripts/migrate-json-to-sqlite.ts — 1회 실행, 원본 db.json은 백업 후 보존
const legacy = JSON.parse(fs.readFileSync('data/db.json', 'utf-8'));

await prisma.$transaction(async (tx) => {
  await tx.pricingItem.createMany({ data: legacy.pricingItems });

  for (const d of legacy.drafts) {
    await tx.draft.create({
      data: {
        id: d.id,
        status: d.status,
        revision: d.revision,
        payload: stripPricingSnapshot(d.payload),   // 용량 절감
        customerName: d.payload.orderEntity?.customerName ?? '',
        projectName:  d.payload.orderEntity?.projectName  ?? '',
        step:         d.payload.step ?? 1,
        totalAmount:  d.payload.calculationResult?.summary?.finalGrandTotal ?? null,
        revisions: { create: d.history.map(toRevisionRow) },
      },
    });
  }

  for (const q of legacy.quotes) {
    await tx.quote.create({ data: toQuoteRow(q) });   // 스냅샷 원본 유지
  }
});
```

## 프레임워크와 무관한 개선

지금 넣어도 값을 하는 것들입니다.

### TanStack Query

현재 `App.tsx` 전체가 `fetchJson` + `useState(loading)` + 수동 재조회의 반복입니다. 캐시·재검증·낙관적 업데이트가 따라오고, 초안 자동 저장도 `useMutation`으로 훨씬 단순해집니다.

### Zod

서버 입력 검증이 `if (!orderEntity)` 수준입니다. 스키마 하나를 클라이언트·서버가 공유하면 검증과 타입 추론이 한 번에 해결됩니다.

### 라우터 (React Router / TanStack Router)

탭이 `useState<'wizard' | 'pricing' | …>`입니다. 그래서 새로고침하면 첫 탭으로 돌아가고, 특정 견적서 링크를 공유할 수 없고, 뒤로가기가 동작하지 않습니다. 취향이 아니라 실제 확장성 결함입니다.

### tRPC (선택)

`fetchJson<{ data: QuoteDraft }>`의 제네릭은 **거짓말을 해도 컴파일됩니다.** 서버가 실제로 그 모양을 반환한다는 보장이 없습니다. 이 프로젝트에서 클라이언트·서버 라우트 불일치로 404가 3건 났던 원인입니다.

### Vitest

`server/calculationEngine.ts`는 순수 함수라 테스트 비용이 거의 없습니다. 돈이 걸린 코드이고, 원가 로직을 다시 손대는 시점이 곧 테스트 환경이 필요해지는 시점입니다.

### server.ts 분할

498줄 단일 파일에 8개 도메인의 라우트가 모여 있습니다. `routes/pricing.ts` · `routes/quotes.ts` · `routes/drafts.ts`로 나누고 비즈니스 로직은 `services/`로 내립니다.
