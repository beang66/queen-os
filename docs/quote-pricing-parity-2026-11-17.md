# Queen-OS 가격 조정·발행 금액 일치 검증 기록

- 기준일: 2026-11-17
- 변경 범위: **3단계 원가 계산 → 4단계 미리보기 → 서버 발행 → 저장·재조회 → 고객용 Excel**
- 검증 환경: AJB 독립 저장소 복사본, Docker PostgreSQL 15 격리 DB, 합성 주문서, 로컬 Chrome
- 결과 구분: **기술적 동작 검증**. 실제 납품·고객 효과·매출·가격 정확도 검증 아님

## 발견 원인

이전 구조는 3단계에서 `src/components/wizard/calc/costModel.ts`로 로스율·목표 마진율·할인·추가금·VAT 포함 여부를 브라우저에서만 계산했습니다. 4단계에서는 기존 서버의 원가표 기반 `calculationResult`를 다시 사용해 공급가가 달랐고, 품목 숨김 시 명세와 총액은 미리보기에서 바뀌지만 서버는 발행을 거부했습니다.

## 구현한 개선

1. `src/domain/quotePricing.ts`: 가격 조정 및 품목 제외를 처리하는 **공유 순수 계산 함수** `projectQuotePrice()` 도입. 원 단위 정수로 품목별 공급가를 배분해 `sum(품목 공급가)=summary.totalSellingPrice`가 성립하게 했습니다.
2. `QuotePublishMeta.pricingAdjustments`에 로스율·목표 마진율·할인액·추가금·VAT 모드를 **발행 조건과 함께 저장**합니다. 예전 초안·API와의 호환을 위해 옵션으로 추가했습니다.
3. 3단계의 가격 조정 컨트롤을 Wizard 상태로 올려 4단계로 이동해도 조건이 사라지지 않도록 수정했습니다. 목표 마진율 변경만으로 불필요한 DB 계산 재호출은 수행하지 않습니다.
4. 3·4단계 미리보기와 서버의 최종 계산은 공유 함수를 사용합니다. 품목 제외 시 해당 품목의 금액도 제외하고 남은 항목에 조정된 공급가·VAT를 다시 계산합니다. 4단계에서 품목을 제외한 뒤 3단계로 돌아가도 동일한 계산 결과를 사용합니다.
5. 서버는 **DB 기준 기본 가격을 재계산**해 클라이언트 원본 결과의 변조/오류를 검증한 후, 같은 공유 함수를 서버에서 다시 실행해 계산 결과만 저장합니다. 마진 설정 충돌·중복/알 수 없는 제외 품목·전체 제외는 발행 거부합니다.
6. 과도한 할인으로 양수 원가 견적의 최종 금액이 0원이 되는 경우 발행하지 않습니다.
7. 실제 발행 이후 4단계는 브라우저 예측값 대신 **서버 저장 결과**를 표시합니다.
8. 기존 Excel 출력은 저장된 서버 계산 결과를 사용하므로 변경된 공급가·VAT·품목 제외 내용과 일치합니다.
9. 발행 완료 후 다음 버전 버튼에 V3가 잘못 표시될 수 있던 **버전 표시의 +1 중복**을 정정했습니다.

## 격리 DB 자동 검증

- 전체 Vitest 테스트 **51/51 통과** (가격배분·VAT·할인·품목 제외·예외 테스트 포함).
- 독립 HTTP API 통합 검증 **27/27 통과** (기존 17건 + 가격조정·품목 제외·VAT 포함 등 신규 검증 10건).
- `npm run build`, `npx tsc --noEmit` 성공.
- 변경 후 자동 회귀 테스트는 `npm run test:quote-safety:e2e`로 반복 실행 가능. 스크립트는 로컬 격리 DB 주소가 아니면 실행을 중지합니다.

## Chrome 브라우저 실제 흐름 (운영 DB 미접근)

1. 합성 주문서 예시 → 규격 검수: 필수 고객·프로젝트·담당자 확인, 예시 단가 연결 → 3단계로 이동 성공.
2. 로스율 **5%**, 목표 마진율 **30%**, 할인액 **17,500원**, 추가금 **8,500원**, **VAT 포함** 입력.
3. 3단계 총액 **₩4,764,970** → 4단계 고객용 미리보기 총액 **₩4,764,970**, 일치.
4. 4단계에서 품목 하나 제외 → 고객용 미리보기 총액 **₩4,331,470**, 차감 반영.
5. 발행 버튼 클릭 → 격리 DB에 합성 견적 발행 완료, 화면에 표시된 저장 후 총액 **₩4,331,470**, 발행 직전 미리보기와 일치.

위 금액은 테스트 데이터로 만들어진 결과이며, 실제 가구 원가·상업 견적·절감 효과를 나타내지 않습니다.

## 명시적인 한계와 다음 과제

- **실제 사업자 정보 미등록:** 고객용 UI와 Excel은 검증용 미리보기이며 정식 고객 발송 금지.
- **금액 표시 반올림:** 품목별 단가를 원 단위로 표기하므로 소수 수량(예: 3.4m)과 곱한 값이 품목 합계와 몇 원 다르게 보일 수 있습니다. 원 단위의 **품목 공급가액 합계와 문서 총액**을 최종 산식 기준으로 삼고, 향후 단가 표시 정책을 명시해야 합니다.
- **실제 AI 추출/도면 OCR:** 실모델 호출 정확도·반복 업무 성과·현업 사용성·현장 자료의 개인정보 권한은 미검증.
- **동시 사용자 및 단가 변동:** 가격변경 직전 경쟁 조건과 권한별 발행 이력은 추가 검증 필요.
- **기존 견적:** 이미 저장된 과거 견적서는 소급 재계산하지 않으며 이전 문서의 차이는 사용자에게 별도 표기할 필요가 있습니다.
- **본 검증은 실제 회사 업무 개선 수치나 유료 고객 사례가 아닙니다.**

### 다음 실무 검증 시나리오
